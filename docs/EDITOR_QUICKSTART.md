# 管理画面での日常編集

サイトを起動したあとは、ブラウザの管理画面で記事・ページ・画像・フォームを編集できます。画面に表示される機能は役割で変わります。公開・編集権限がない場合はサイト管理者に依頼してください。

## 記事を書く・公開する

1. サイドバーの「投稿」から追加し、見出しと本文を入力します。画像・書式・リンクも本文で編集できます。
2. 「プレビュー」で公開前の見え方を確認します。「下書き」で保存したものは公開されません。
3. 公開状態と公開日時を確認して保存し、「公開ページを見る」で表示を確かめます。未来の日時は予約公開になります。
4. 保存後に一覧から記事を開き直せます。履歴では以前の内容の確認・復元ができます。複製は別URLの下書きになります。

PCでは本文を広く、スマホでは本文を先に表示します。掲載順の上下ボタンは一覧のページをまたいで動かせます。検索中は検索を解除してから並べ替えます。

## 記事のURLを変更するとき

公開済みの記事でURLの末尾（slug）を変更すると、古いURLでは記事が見つからなくなります。**記事単体の変更は自動でリダイレクトを作りません。**

1. 編集画面の案内にある変更前のURLを控えます。
2. URLを変更して保存し、編集画面の「公開ページを見る」で新しいURLを確認します。
3. 「リダイレクト」で転送元に旧URLのパス（例 `/blog/old-name`）、転送先に新URL（例 `/blog/new-name`）を入力し、301で保存します。
4. シミュレーターで転送先を確認します。301はブラウザに記憶されるため、試行中はシミュレーターを使ってください。

投稿タイプ全体の入口を変える機能は別です。対応する入口変更では自動転送を作り、引き継げない構造変更は保存前に止めます。

## 独自の項目を追加する

「投稿タイプ」から型を追加・設定し、設定画面の「カスタムフィールド」へ進みます。項目の表示名・種類・割当先を指定して作成すると、その型の編集画面で入力できます。繰り返し・グループ・参照・複数画像等も選べます。標準項目の構造変更とは分けて扱います。

## ページ・既存HTML

ページではブロックの本文・画像・リンク・順序を編集し、保存して公開できます。条件を満たす取り込みHTMLは、元の枠を保ったままページとして編集できます。変換できない動的な部分は読み取り専用になるか取り込み前に停止します。任意のPHP・WordPressプラグインがそのまま動く仕組みではありません。

## バックアップ・一括置換・書き出し

- バックアップ画面では処理中・完了・失敗を確認できます。復元は現在のDBとメディアを変えるため、対象と検証結果を確認して実行します。コードや独自テーマの保全はプロジェクトのGit・配布物の保全と合わせます。
- Ownerの「一括置換」は、条件→対象と抜粋の確認→実行の順です。24時間以内の検証済みバックアップが必要です。1回200件までの文字どおりの置換で、正規表現やJSON内項目は対象外です。
- Ownerの内容書き出しは記事とページ等のXMLです。画像の実ファイル・テーマ・ユーザー・フォーム設定を含む完全なサイト複製ではありません。サイト全体の移動にはバックアップとプロジェクトファイルを使用します。

## 保守と更新

「公開・保守チェック」で確認結果を読みます。署名確認済みでも更新は未実行です。配布物未照合・古い記録・失敗は別に表示されます。コードの更新とサーバーの定期確認設定は、バックアップ・差分・移行手順を確認できるサーバー管理者が行います。

### WordPressへ持ち出すときの照合

XMLをWordPressへ取り込んだら、記事・ページの件数、本文、公開状態を照合します。同じタイトル・日時・投稿種別が複数あると、WordPress側が重複と判定することがあります。意図した別記事なら、元サイトを残した移行用の複製で識別できるタイトルへ変更してから書き出してください。投稿者は取り込み画面で割り当てます。デザインや画像ファイル、独自項目の表示は別途移行します。
