# 実装の引き継ぎ・受け入れ報告

<!-- 2026-09-18: 報告のためのコミットや定型の空欄埋めを要求しない。 -->
結論、変更の目的、実行した検証と結果、残る未確認事項を示す。計画から省いた項目や追加した範囲があれば理由を書く。

- コミット済みならhash、未コミットならその状態と対象ファイルを示す。報告形式を満たすためにコミットしない。
- テストの件数・skip・失敗は取得できた結果を使う。実行していない検証を成功扱いにしない。
- リンクは実在する根拠へ向ける。kit、generated project、実ブラウザ、配布物、インストール済みアプリの結果を区別する。
- 通常の小さな修正は短い報告で足りる。複数機能の受け入れや引き継ぎでは項目別に示す。
- 仕様や公開範囲の選択が必要なら、現状と推奨案を添えて確認する。局所的な実装判断で毎回停止しない。

このスキルは外部のdirector等への送信許可を与えない。現在の会話へ報告し、外部送信は明示された依頼範囲だけで行う。
