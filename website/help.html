BEFORE YOU START

必要なものを準備する

Mac
Apple Silicon搭載Mac（M1以降）
Windows
Windows 11・WSL2・Ubuntu 24.04
共通
起動したDocker Desktop、初回セットアップ用のインターネット接続

GUI版にはNode.jsを同梱しています。PHP・Composer・pnpmもパソコンへ別途入れる必要はありません。Gitは任意です。CLI版だけを利用する場合のNode.js導入手順は下の「コマンドで導入する」にあります。

スマホは、公開したサイトの管理画面で日常更新するときに使えます。最初の制作環境はMacまたはWindowsに用意します。AIサービスやサーバーなどの契約は別途必要です。

Desktop 2.6で新しく作るローカルサイトは、このパソコン内からだけ開けます。サイトの一覧や記事は配布アプリに含まれません。ステージング・本番への公開は、接続先を設定してデプロイしたときに行われます。

MAC

アプリを開いて始める

  1. Docker Desktopを起動する

    未導入なら公式案内からApple Silicon版をインストールし、起動完了を待ちます。

  2. DMGを開いてアプリを入れる

    sitegrowkit-desktop-2.6-0.9.4-rc5-macos-arm64.dmgをダブルクリックします。中のSiteGrowKit.appをApplicationsへドラッグしてください。ZIP版を使う場合は、展開したアプリをアプリケーションフォルダへ移します。

  3. SiteGrowKitをダブルクリックする

    初回はブラウザにWelcome画面が開きます。「はじめる」から環境を確認し、「新しいサイトをつくる」または「作成済みのサイトを追加」を選びます。案内を終えた後は、次回からサイト一覧が直接開きます。

Mac版 Desktop 2.6は、DOGGO COMPANY K.KのDeveloper IDで署名し、Appleの公証を受けています。公証チケットもアプリに添付済みです。以前の未署名版をお持ちの場合は、Desktop 2.6の配布ファイルを取得し直してください。

WINDOWS

Windowsもダブルクリックから

  1. 最初の環境を用意する

    WSL2、Ubuntu 24.04、Docker Desktopを用意します。導入済みなら再インストールは不要です。Windowsの「Windowsの機能の有効化または無効化」で「仮想マシンプラットフォーム」を有効にし、必要な再起動を行います。Microsoft Storeから「Windows Subsystem for Linux」と「Ubuntu 24.04 LTS」を導入してください。Ubuntuを一度開き、ユーザー名とパスワードを設定します。

    Docker Desktopの「Settings → Resources → WSL Integration」でUbuntu 24.04を有効にします。MicrosoftのWSL導入案内とUbuntuの導入案内も参照してください。PCの構成によって管理者権限や再起動が必要です。

  2. GUI版のZIPをすべて展開する

    sitegrowkit-desktop-2.6-0.9.4-rc5-windows-x64.zipを右クリックして「すべて展開」を選びます。フォルダ全体を一緒に保存してください。

  3. SiteGrowKit.exeを開く

    起動準備の表示後、初回はブラウザにWelcome画面が開きます。「はじめる」から環境を確認してください。WindowsやUbuntuへのNode.jsの追加インストールは不要です。exeだけを別の場所へ移動せず、必要ならショートカットを作成してください。

このGUI版はローカル確認用です。Windowsの発行者署名は未実施のため、セキュリティの警告が表示される場合があります。

初回の案内は「あとで設定する サイト一覧へ」で後回しにもできます。もう一度見たいときは、サイト一覧右上の「はじめ方」を押してください。環境の確認に失敗したときは、案内に沿って準備し「もう一度確認」を押します。

FIRST SITE

最初のサイトを作る

Docker Desktopを起動した状態でSiteGrowKitアプリを開き、サイト一覧の「新しいサイト」を押します。

  1. 環境を確認する

    ブラウザで「はじめる」を押します。足りないものが表示されたら、画面の案内に従って準備し、確認をやり直します。

  2. サイト名と保存場所を決める

    サイト名とフォルダ名を入力します。既定の保存先はホームフォルダ内の SiteGrowKit Projects です。WindowsではLinux側の場所を選んでください。

  3. 準備の完了を待つ

    作成・起動・ファイルの準備・動作確認が順番に進みます。初回はダウンロードに時間がかかります。処理中はDocker Desktopを終了せず、ブラウザの進行状況を確認してください。

  4. サイトと管理画面を開く

    「準備ができました」と表示されたら、「サイトを見る」「管理画面を開く」へ進めます。URLのポート番号は環境によって異なるため、完了画面に表示されたURLを使ってください。

ここでできるのは、自分のパソコンで動く制作環境です。インターネットへ一般公開する操作は含まれません。

FIRST UPDATE

ログインして更新を始める

サイト一覧で対象サイトを起動し、「ログイン情報・再設定」を押します。ログイン用メールアドレスを確認・コピーできます。初期パスワードが今も有効なら、伏せ字で表示されます。「表示」または「コピー」を押して利用してください。

パスワードが分からない・変更済みの場合

  1. 管理者を選ぶ

    「ログイン情報・再設定」で、入りたい管理者のメールアドレスを選びます。

  2. 再設定画面を開く

    対象サイトを確認してチェックを付け、「再設定画面を開く」を押します。メールの受信は不要です。

  3. 新しいパスワードを設定する

    別のタブで開いた画面に新しいパスワードを入力し、設定後に管理画面へログインします。タブが開かなければ、表示された再設定リンクを押してください。

この機能はローカルサイト専用です。再設定リンクは表示された有効時間内に1回だけ使えます。記事・画像や管理者の権限は変わりません。二段階認証を設定している場合は、引き続き認証コードまたはリカバリーコードが必要です。画面内のログイン情報は60秒後、または画面を閉じると消えます。コピーした内容はクリップボードに残ります。

  • 「サイト設定」で名前やロゴを設定する
  • 最初の記事・ページを下書きで保存し、プレビューから公開する
  • メニューを案件に合わせる
  • お問い合わせの通知先とメール設定を確認する
  • 「公開・保守チェック」で公開前の指摘を確認する

ローカル開発時のメールはテスト用の受信画面で確認します。本番メールの実配達は、公開するサーバーで設定・確認が必要です。

日常の編集は、同梱の docs/EDITOR_QUICKSTART.md にまとめています。

DAILY USE

次回からはサイト一覧で操作

  1. SiteGrowKitアプリを開く

    作成したサイトが一覧に表示されます。別の場所にあるサイトは「フォルダから追加」から選びます。実行されるプログラムが含まれるため、自分で作成したもの、または信頼できる相手から受け取ったフォルダだけを追加してください。

  2. 「起動」を押す

    準備中の工程と経過時間が表示されます。「稼働中」になったら「管理画面を開く」または「サイトを見る」を押します。「未確認」は、稼働状態を確認できていないことを示します。

  3. 作業が終わったら「停止」

    対象サイトの「停止」を押します。記事・画像・データは残ります。ブラウザやアプリを閉じるだけではサイトは停止しません。

「アプリを終了」はサイト一覧だけを終了します。新規作成の設定画面を開いている間は、他のサイトの起動・停止を待ってください。

PUBLISH

ステージングと本番も同じ画面で

Desktop 2では、サイトを選んで「ローカル」「ステージング」「本番」を切り替えられます。公開先の接続設定・接続確認・公開・旧版への切り戻しを、ボタンで操作します。

  1. 公開先を登録する

    「ステージング」または「本番」を選び、「公開先の接続設定」にURL、SSHホスト・ユーザー、アプリ保存先と公開フォルダを入力して保存します。対応サーバーはXserverです。ステージングと本番は別のURL・配置先にしてください。

  2. 接続と公開内容を確認する

    「接続を確認」で不足項目を確認します。「公開内容を確認」では、このパソコンで公開用ファイルを作成し、公開先・データベース変更・バックアップなどを表示します。

  3. 確認して公開する

    表示された内容を確認し、チェックを付けて「ステージングへ公開する」または「本番へ公開する」を押します。処理中は工程と経過時間、完了後は確認結果が表示されます。確認後にソースや公開先が変わった場合はやり直してください。

  4. 公開後も状態を確認する

    接続確認と操作履歴を同じ画面で確認できます。「旧版へ切り戻す」では対象版を確認してから実行します。DB・記事・画像は過去の状態に戻りません。

初回のサーバー準備（契約・ドメイン・SSL・DB・SSH公開鍵・サーバー側の初期設定）は別途必要です。SSHの初回本人確認や鍵のパスフレーズ解除は既存のMac／Ubuntu側の設定を使います。このGUIでは初期設定の自動代行や、ステージングDBの本番同期は行いません。

詳しくは同梱の docs/release-20260909/desktop2-guide.md を参照してください。公開中はソースの編集とDocker Desktopの終了を避けてください。

WITH AI

AIと制作を始める

Claude Code、Codex、Cursorなどで作成したサイトのフォルダを開き、作りたい内容を伝えます。セットアップ完了画面の「AIエージェント連携」から、対応する設定ファイルも作成できます。

AIへ渡す依頼の例
このプロジェクトのAGENTS.mdまたはCLAUDE.mdと、.agentcms/のルールを読んでください。
core/は変更せず、作業後はagentcms verifyと実際の画面で確認してください。
依頼：会社紹介、サービス案内、お問い合わせを備えたサイトを作ってください。

エージェント本体とサービスの契約は別途必要です。詳しくは同梱の docs/AI_AGENTS.md を参照してください。

HELP & FAQ

困ったとき

GUI版では「新しいサイト」の環境チェックや、サイト一覧の状態表示を確認してください。次の診断コマンドはCLI版を利用する場合の補足です。

環境を診断する
agentcms doctor

npmやnodeが見つからない

Node.jsを入れた後にターミナルを開き直してください。WindowsではUbuntu内のNode.jsが必要です。node --version と npm --version の両方が動くことを確認します。

.tgzが見つからない・ENOENTと表示される

展開したフォルダへ移動できているか確認してください。フォルダ名は agent-cms-kit-v0.9.4-rc5、ファイル名は agent-cms-kit-0.9.4-rc5.tgz です。ファイル名には v が付きません。

インストール時にEACCES・Permission deniedが出る

npmのインストール先へ書き込めていません。利用しているNode.jsの導入方法と保存先を確認してください。ユーザー権限で使えるNode.js環境へ切り替える方法は、Node.jsやMicrosoftの公式導入案内を参照してください。エラーだけを避けるために sudo npm install -g や chmod -R 777 を実行しないでください。

agentcmsが見つからない・違う版が表示される

インストールした時と同じNode.js環境を使っているか確認します。npm prefix -g の配下の bin がPATHに入っている必要があります。nvmなどでNode.jsの版を切り替えた場合は、CLIを入れた版へ戻して確認してください。

Dockerへ接続できない

Docker Desktopを起動して、起動完了を待ってください。WindowsはWSL Integrationで使用するUbuntuが有効か確認します。SSH経由だけで認証エラーが出る場合は、Windowsへサインインした状態で、PC上のUbuntuターミナルから再実行してください。

セットアップ画面が開かない・途中で止まった

ブラウザを自動で開けない場合は、ターミナルに案内されるURLを開きます。URLには一時的な認証情報が含まれるため、共有しないでください。画面に失敗が表示されたときは「詳細」と復旧案内を確認し、「もう一度試す」または続きからの再開へ進みます。

作成済みサイトの再起動は、そのサイトのフォルダで agentcms dev を実行します。困った場合はフォルダを削除せず、失敗したコマンドとエラーを保管してください。

ログイン情報が分からない

Desktop 2.6で対象のローカルサイトを起動し、「ログイン情報・再設定」を押してください。有効な初期パスワードを確認するか、管理者を選んで新しいパスワードを設定できます。初期情報のファイルがなくても、有効な管理者がいれば再設定できます。古いアプリではボタンが表示されないため、Desktop 2.6を開き直してください。

投稿を公開したのにサイトに出ない

記事の公開状態と公開日時に加え、投稿タイプ自体の公開設定を確認してください。編集画面に非公開の理由が表示されている場合は、案内から設定へ進めます。

WordPressをそのまま移せる？

rc5はWXRの投稿・分類・対応するページなどを取り込めます。先に診断して未対応データを確認します。WordPressのPHPテーマ・プラグインの互換実行やメニューの完全自動移行は行いません。配布READMEの「ページは持ち込まない」という旧案内はrc5には当てはまりません。

問い合わせフォームから実メールが届かない

ローカル開発ではテスト用の受信画面を確認します。公開時は本番用の送信方法と通知先を設定し、実際に届くところまで確認してください。送信完了画面だけで実配達を判断しないでください。

コマンドで導入する（従来のCLI版）

MAC

Macでインストール

  1. DockerとNode.jsを用意する

    Docker Desktopの公式案内からApple Silicon版をインストールして起動します。Node.jsがなければ公式ダウンロードページからLTS版を入れます。入れた後はターミナルを開き直してください。

    Node.jsの確認
    node --version
npm --version

    バージョン番号が表示されれば準備できています。

  2. 展開したフォルダを開く

    ZIPをダブルクリックして展開します。すでに agent-cms-kit-v0.9.4-rc5 フォルダがあれば、そのまま使えます。

    「ターミナル」を開き、cd と半角スペースを入力してから、Finderのフォルダをターミナルへドラッグし、Returnを押してください。ダウンロードフォルダへ展開した場合は次のコマンドでも移動できます。

    ダウンロードフォルダからの移動
    cd ~/Downloads/agent-cms-kit-v0.9.4-rc5

    保存場所が違うときは、この例をそのまま実行せず、フォルダをドラッグする方法を使ってください。

  3. SiteGrowKitをインストールする

    Macの導入コマンド
    npm install -g ./agent-cms-kit-0.9.4-rc5.tgz
agentcms --version

    0.9.4-rc5 が表示されればインストール完了です。続いて最初のサイトを作るへ進みます。

    すでに別の版のCLIがある場合、この操作でCLIの版が切り替わります。作成済みサイトの更新は別の操作です。

WINDOWS

Windowsでインストール

SiteGrowKitのコマンドはWSL2のUbuntu内で実行します。 PowerShellは、下のWSL導入時だけ使用します。作業場所はLinux側の ~/ 配下にしてください。

  1. WSL2を用意する

    まだWSLを入れていない場合は、PowerShellを管理者として開いて実行します。表示された案内に従って再起動し、Ubuntuの利用者名とパスワードを設定してください。

    PowerShellでWSLを導入
    wsl --install

  2. DockerのWSL連携を有効にする

    Docker Desktopを起動し、Settings → Resources → WSL Integrationで使用するUbuntuを有効にします。Docker公式のWSL設定で確認できます。

    Ubuntu内でNode.jsを用意します。MicrosoftのNode.js導入手順に従い、サポート中のLTS版を選びます。Windows側に入れたNode.jsだけでは準備完了になりません。

    Ubuntu内のNode.jsを確認
    node --version
npm --version

  3. ZIPをLinux側へコピーして展開する

    Ubuntuのターミナルで次を実行します。展開先フォルダがWindowsのエクスプローラーで開きます。

    Linux側の保存先を開く
    mkdir -p ~/sitegrowkit-download
cd ~/sitegrowkit-download
explorer.exe .

    開いた場所へ agent-cms-kit-v0.9.4-rc5.zip をコピーし、Ubuntuのターミナルで展開します。すでにLinux側に展開済みなら、そのフォルダへ移動してください。

    UbuntuでZIPを展開
    unzip agent-cms-kit-v0.9.4-rc5.zip
cd agent-cms-kit-v0.9.4-rc5

    unzip: command not found と出た場合だけ、sudo apt update と sudo apt install unzip を実行してからやり直します。/mnt/c や /mnt/d はプロジェクトの作業場所に使いません。

  4. SiteGrowKitをインストールする

    Ubuntuの導入コマンド
    npm install -g ./agent-cms-kit-0.9.4-rc5.tgz
agentcms --version

    0.9.4-rc5 と表示されたら、次へ進みます。

CLI版から設定画面を開く

CLI版だけを使う場合は、次のコマンドでセットアップを開きます。

セットアップ画面を開く
agentcms setup

EVERYDAY

次回の起動と終了

作成したサイトのフォルダへ移動してから実行します。インストール用の .tgz があるフォルダとは別です。下はフォルダ名を my-site にした場合の例です。

作成したサイトへ移動する例
cd "$HOME/SiteGrowKit Projects/my-site"

サイトを起動する
agentcms dev

終了するときは次を実行します。通常の停止でサイトのデータは削除されません。

サイトを停止する
agentcms stop

ブラウザを閉じるだけではDockerのサイトは停止しません。新しいサイトをもう1つ作る場合は、agentcms setup で別のフォルダ名を指定します。

FILES

ファイルと確認方法

.dmg
Mac版のインストール用ディスクイメージ。開いてアプリをApplicationsへドラッグします。
.zip
製品の配布ファイル。展開して使います。
.tgz
展開したフォルダ内にある、npmでインストールする本体です。
docs/
編集、Windows、移行、更新、復旧などの詳しいガイドです。
ダウンロードしたZIPのハッシュを確認する

配布元から取得した .zip.sha256 とZIPを同じフォルダに置き、そのフォルダで実行します。検証用ファイルが手元にない場合は、配布元へ確認してください。

MacでZIPを照合
shasum -a 256 -c agent-cms-kit-v0.9.4-rc5.zip.sha256

UbuntuでZIPを照合
sha256sum -c agent-cms-kit-v0.9.4-rc5.zip.sha256

OK なら記録されたハッシュと一致しています。発行者を確認する署名検証は、独立した経路で取得した公開鍵を使い、docs/UPGRADING.md の手順に従ってください。

このページは0.9.4-rc5向けです。ファイル名に旧名「Agent CMS Kit」が残りますが、製品名はSiteGrowKitです。

解決しないときは

MacかWindowsか、使っている版、押したボタン、表示されたエラーを添えてご連絡ください。パスワード・認証用URL・.env の内容は送らないでください。
